1. EXECUTIVE SUMMARY & DESIGN PHILOSOPHY
================================================================================
AUREX (Mark LIV) is an autonomous, cross-platform personal AI assistant developed
by Hammad Nawaz. Unlike conventional assistants that rely on cloud speech-to-text
followed by text LLM generation and cloud text-to-speech, AUREX is built directly
on top of the Gemini Live WebSocket API (`models/gemini-3.1-flash-live-preview`).

Core Architectural Tenets:
1. Native Audio Streaming: Bidirectional streaming (16 kHz PCM microphone input,
   24 kHz PCM assistant speech output) provides sub-second latency and natural
   human conversational pacing without intermediate transcription lags.
2. Zero GPU Hardware-Agnostic Holographic Head: A fully custom 3D holographic
   face renderer executing entirely on CPU via PyQt6 QPainter and NumPy. It runs
   identically on high-end gaming workstations, ten-year-old laptops, virtual
   machines, and remote desktop sessions.
3. Physics + Linguistic Multilingual Lip-Sync: Mouth articulators calculate real
   F1/F2 audio formants combined with Unicode-normalized text viseme schedules,
   accurately articulating stop-consonants (/m/, /b/, /p/) and vowels without
   language-specific phoneme tables.
4. Digital Autonomy & Full Computer Use: AUREX controls the local desktop
   environment—manipulating files, adjusting hardware settings, navigating
   browsers with Playwright/CDP, inspecting UI automation trees, clicking buttons,
   and solving online multiple-choice questions (MCQs).
5. Unforgeable Security & Deep Reversibility: Destructive or irreversible actions
   (shutdown, reboot, WiFi disabling) are physically gated behind an on-screen
   human confirmation widget that the LLM cannot self-confirm. Reversible actions
   (file moves, edits, creation, settings) push onto an integrated Undo stack.

3. CORE ARCHITECTURE & LIFECYCLE (main.py)
================================================================================
`main.py` is the central operational spine of AUREX. It binds the PyQt6 GUI,
Gemini Live WebSocket session, audio devices, and tool execution engines.

Key Responsibilities & Components:
- Windows Subprocess Hardening: Overrides `subprocess.Popen` on Windows to enforce
  `CREATE_NO_WINDOW`, eliminating flashing command prompt windows across all tools.
- Console Code Page Sanitization: Reconfigures stdout and stderr streams to UTF-8
  with replacement fallbacks, ensuring foreign characters and emojis never crash
  legacy console environments (e.g., cp1252, cp1254, cp932).
- Audio Pipeline:
  * Input Stream: `sounddevice.InputStream` captures 16,000 Hz, 16-bit mono PCM.
    Transfers frames into `_mic_queue` via zero-copy buffering.
  * Output Stream: `sounddevice.OutputStream` outputs 24,000 Hz, 16-bit mono PCM.
    Plays incoming audio chunks from Gemini Live.
  * Real-Time RMS Loudness: `_pcm_level()` computes Root-Mean-Square volume with
    a calibrated noise floor (60.0 to 2600.0) mapped into a 0.0–1.0 float.
- Gemini Live Session Loop (`_live_session_loop`):
  * Connects to `models/gemini-3.1-flash-live-preview` using `google.genai.Client`.
  * Passes `LiveConnectConfig` with native `AUDIO` modalities, configured voice
    (e.g., Puck, Charon, Kore, Fenrir, Aoede), and system instructions.
  * Dynamically populates tools from both `ActionRegistry` and `PluginRegistry`.
- Concurrency Model:
  * Audio I/O threads run asynchronously off the main thread.
  * Incoming Gemini Live messages (`receive()`) stream text chunks, audio PCM,
    and `ToolCall` events.
  * Non-blocking tool dispatch: Tools execute in worker thread pools. When a tool
    starts, AUREX immediately issues an audible spoken acknowledgment in the
    user's language to prevent silent waiting gaps.
- Session Continuity & Error Recovery:
  * Maintains a rolling history of conversation turns in `memory/recent_chat.json`.
  * Recovers gracefully from network disconnects or WebSocket 1011 errors by
    re-establishing sessions while injecting conversational context.

4. HOLOGRAPHIC AVATAR & VISEME SUBSYSTEM
================================================================================
Files: `core/avatar.py`, `core/avatar_mesh.py`, `core/viseme.py`, `core/face_model.obj`

1. Pure Software Rendering:
   - Built entirely with PyQt6 `QPainter`.
   - Bypasses OpenGL, DirectX, and Vulkan drivers completely. Eliminates driver
     crashes, GPU power draw, and cross-platform shader incompatibilities.
   - Executes at a buttery 60 FPS (throttling dynamically down to 30 FPS or 20 FPS
     when idle).

2. 3D Geometric Mesh (`core/avatar_mesh.py`):
   - Face topology is constructed from MediaPipe's canonical 3D human face model
     (`core/face_model.obj`), comprising measured anatomic facial landmarks.
   - Generates procedural skull structure, neck columns, jaw pivot hierarchy,
     and eyelid contours at startup.
   - Projects 3D vertices (X, Y, Z) to 2D screen coordinates using a perspective
     pinhole camera model (camera distance `_CAM_D = 4.6` head-half-heights).
   - Depth sorting: Facets and lines are sorted along the Z-axis, with wireframe
     lattice alpha opacities grouped into batched `drawLines()` calls.

3. Multilingual Dual-Source Lip-Sync (`core/viseme.py`):
   - Audio Formant Analysis: `_pcm_visemes()` evaluates 20 ms PCM audio slices
     using Fast Fourier Transforms (FFT).
     * F1 (150–1100 Hz): Determines jaw openness (close vs open vowels).
     * F2 (600–3200 Hz): Determines lip width (spread vs rounded vowels).
   - Transcript Consonant Fusion: High-frequency audio spectrum cannot reliably
     distinguish bilabial closures (/m/, /b/, /p/). AUREX inspects the model's
     spoken text stream to forcibly close the lips on plosives and nasals.
   - Universal Unicode Reduction: Strips accents and diacritics using Unicode
     NFD decomposition; transliterates Cyrillic and Greek characters into Latin
     bases. All Western and Slavic languages share one coherent viseme table.

4. Expressive Facial Acting & Behavioral States:
   - State-Reflective Gaze:
     * Listening: Gaze fixes directly forward, eye contact locked on user.
     * Thinking: Eyes saccade upward and away.
     * Speaking: Periodic micro-saccades and natural blinks.
     * Asleep: Eyelids lower gently to rest.
   - Brow Rig: Brows subtly lift on vocal emphasis or high audio formants.
   - Theme Adaptability: Shading lookup table (`_LUT_N = 192`) dynamically re-tints
     to match the active HUD accent color from the UI hue wheel.

5. ACOUSTIC PIPELINE & AUDIO CONTROL
================================================================================
Files: `core/echo.py`, `core/audio_devices.py`, `core/wake_word.py`

1. Self-Echo Guard (`core/echo.py`):
   - Prevents the assistant from hearing its own voice played through the speakers
     without blindly muting the microphone.
   - Band Energy Fingerprinting: Splits incoming microphone audio and outgoing
     speaker audio into log-spaced speech frequency bands (200 Hz to 7000 Hz).
   - Spectral Subtraction: Subtracts recent speaker output bands from incoming
     microphone frames. Residual energy of self-speech drops near zero, whereas
     a human user speaking simultaneously introduces distinct formants that survive
     subtraction.
   - Dynamic Acoustic Calibration: Continuously tracks speaker-to-mic gain ratios,
     adapting on the fly to volume knob adjustments or room acoustics.

2. Audio Device Picker & Host API Resolution (`core/audio_devices.py`):
   - Standard `sounddevice` enumerates all combinations of devices and host APIs
     (MME, DirectSound, WASAPI, WDM-KS, ALSA, CoreAudio), yielding dozens of
     confusing duplicate entries.
   - Intelligently filters out virtual sound mappers, zero-channel endpoints,
     and duplicates, presenting only genuine hardware names.
   - Probes sample rate capabilities (16 kHz in / 24 kHz out) on background
     worker threads to prevent UI freezes.

3. Local Wake-Word Engine (`core/wake_word.py`):
   - Integrates `openwakeword` for local, zero-cloud detection of "Hey Aurex"
     (custom ONNX model) and "Hey Jarvis".
   - Non-blocking Queue Architecture: Audio callback feeds a low-overhead queue;
     inference executes on a dedicated background thread.
   - Zero CPU consumption when wake-word mode is toggled off in settings.

6. SAFETY & REVERSIBILITY FRAMEWORK
================================================================================
Files: `core/confirm.py`, `core/undo.py`

1. Unforgeable Confirmation Gate (`core/confirm.py`):
   - Problem: In traditional LLM assistants, confirming an action is done via a
     parameter like `confirmed=true`. The LLM can easily hallucinate or forge
     this flag on its first attempt.
   - Solution: Hazardous tools (e.g., system shutdown, OS restart, WiFi toggle)
     call `confirm.request()`.
   - The method registers an in-memory pending task with a cryptographic random
     key, immediately presents a physical PyQt6 confirmation banner on the HUD,
     and returns an instruction for the assistant to verbally ask the user.
   - Execution occurs IF AND ONLY IF the physical human user clicks "CONFIRM"
     on screen. Auto-expires after 90 seconds.

2. Universal Undo Stack (`core/undo.py`):
   - Thread-safe LIFO stack holding the last 10 reversible operations.
   - Reversible actions (file movement, renaming, content writing, settings
     alterations) register a lambda inverse closure upon success.
   - Example: Writing a file captures its previous text; moving a file captures
     its source path.
   - When the user says "undo that", "revert that", or "put it back", AUREX
     pops the top entry and executes its reversal logic cleanly.

7. GEMINI LLM CLIENTS & RESILIENCE LADDER
================================================================================
Files: `core/gemini.py`, `core/llm_client.py`

AUREX separates conversational speech from single-shot intelligence calls (such
as OCR analysis, flight extraction, code generation, and dev agent planning).

The Resilience Ladder:
1. Primary Tier: Ephemeral throwaway Gemini Live sessions. Leverages the separate
   Live API quota pool, preserving the standard REST quota for critical tasks.
2. Secondary Tier: Pinned REST models (`gemini-2.5-flash`, `gemini-2.5-flash-lite`).
3. Tertiary Fallback: Dynamic rolling aliases (`gemini-flash-latest`).
4. Strict Timeout Safeguards: Every single REST call enforces an explicit timeout
   (default 15–60 seconds). Network hangs or 504 errors fail immediately down to
   the next rung on the ladder rather than stalling the assistant indefinitely.

8. DISCOVERY ENGINES & PLUGIN EXTENSIBILITY
================================================================================
Files: `core/action_loader.py`, `core/plugin_loader.py`

AUREX decouples tool definitions from the core codebase. Adding a new tool
requires zero edits to `main.py`.

1. Action Discovery (`core/action_loader.py`):
   - Scans `actions/*.py` at launch using `importlib.util`.
   - Looks for a module-level `TOOL` dictionary specifying:
     * `name`: Function identifier string.
     * `description`: Capability summary read by Gemini Live for routing.
     * `parameters`: JSON Schema describing inputs.
     * `handler`: Callable function.
     * Optional `behavior` ("BLOCKING" / "NON_BLOCKING") and `scheduling` ("WHEN_IDLE" / "SILENT").
   - Signature Introspection: The handler automatically receives `parameters`
     plus any requested context injections (`player`, `speak`, `session_memory`).

2. Plugin Discovery (`core/plugin_loader.py`):
   - Scans `plugins/*.py` for drop-in modular plugins.
   - Inspects `PLUGIN` dictionary declarations.
   - Isolates broken plugins: Syntax errors or missing libraries in one plugin
     are logged and skipped without impairing other modules or stopping startup.

9. SYSTEM PROTOCOLS & RUNTIME SELF-KNOWLEDGE (core/prompt.txt)
================================================================================
`core/prompt.txt` establishes the persona, operational protocol, and behavioral
constraints of AUREX.

Key Directives:
- First-Person Embodiment: The animated head is the assistant's face ("my face",
  "I look"). Screen captures showing the HUD are treated as looking into a mirror.
- Distinguishing Camera vs Screen: A webcam frame depicts the USER; a screen capture
  depicts the COMPUTER.
- Runtime Self-Knowledge: Tokens `{assistant_name}`, `{platform}`, `{capabilities}`,
  and `{limits}` are compiled at launch from the live system environment.
- Level Voice & Tone: Composed, dry understatement, respectful operator register.
  No sycophantic praise ("Good question!"), no robotic hedging, no trailing filler.
- Immediate Acknowledgment Before Silences: When an action requires processing time,
  AUREX speaks a single short sentence in the conversation's active language
  confirming the action before invoking the tool within the same turn.
- Linguistic Continuity: Dynamically matches the user's latest spoken language
  (Urdu, Hindi, English, Turkish, Spanish, etc.) without code-mixing or drifting.

13. REMOTE WEB DASHBOARD & MOBILE CONTROL (dashboard/server.py)
================================================================================
AUREX includes a local HTTP server that allows users to control the assistant from
their smartphone or another machine on the local network.

Technical Architecture:
- Framework: Built on FastAPI and Uvicorn running on port 8000.
- Application-Layer Cryptography:
  * Eliminates browser HTTPS self-signed certificate warnings by running over
    plain HTTP with end-to-end AES-256-CBC encryption.
  * Server generates an 8-character pairing session key.
  * Key derivation: SHA-256(sessionKey + salt) yields a 32-byte AES key.
  * Client-side JavaScript uses CryptoJS (auto-downloaded and cached locally)
    to encrypt and decrypt all WebSocket payloads.
- QR Code Instant Pairing: The desktop HUD displays a high-resolution QR code;
  scanning it with a mobile camera connects instantly without manual typing.
- Mobile Capabilities: Full text chat, real-time voice streaming, system status
  monitoring, and multi-file drag-and-drop uploads.

14. MEMORY & CONTEXT PERSISTENCE
================================================================================
Files: `memory/memory_manager.py`, `memory/config_manager.py`

1. Two-Tier Memory Storage Architecture:
   - Challenge: Traditional assistants append their entire memory file into the
     system prompt, which wastes prompt tokens, inflates latency, and hits limits.
   - Solution:
     * Tier 1 (Core Prompt Memory, ~900 chars): High-priority facts (user identity,
       primary language, active projects) injected into every session prompt.
     * Tier 2 (Disk-Backed Long-Term Store, up to 200,000 chars): Stored in
       `memory/long_term.json`. Retrieved on demand via the `recall_memory` tool.
   - Silent Language Detection: Automatically observes the user's natural language,
     recording it into memory (`identity.language`) to ensure future sessions
     boot into the user's preferred language.

2. Session Summaries & Morning Briefing:
   - On session teardown, conversations are condensed into a 2-sentence summary
     saved to `memory/long_term.json`.
   - On the first startup of a new day, AUREX reads the previous session summary,
     greets the user by name, reports the time, recaps yesterday's projects,
     and offers relevant morning news.

Voice Command Execution Trace:
1. User speaks: "Check D drive college folder and summarize lecture.pdf"
2. Audio Stream: Captured at 16 kHz int16 PCM -> `_pcm_level()` updates HUD waveform.
3. Gemini Live Engine: Receives PCM stream -> Determines tool call is required.
4. Spoken Acknowledgment: AUREX immediately responds out loud: "Checking your college folder now, sir."
5. Tool Dispatch: `ActionRegistry.run("file_processor", {...})` runs in a worker thread.
6. Execution: `actions/file_processor.py` resolves the path, extracts PDF text, and condenses key topics.
7. Return Data: Summary data is returned to Gemini Live.
8. Synthesis & Lip-Sync: Gemini streams 24 kHz audio response -> `_pcm_visemes()` slices
   audio formants -> Avatar mouth articulates with precise closures and vowel shapes.

Hazardous Operation Confirmation Trace:
1. User speaks: "Shut down the computer"
2. Tool Dispatch: `computer_settings.py` calls `confirm.request("shutdown", ...)`
3. Safety Gate: Generates pending key, triggers Qt signal -> HUD shows "CONFIRM SHUTDOWN" banner.
4. Verbal Response: AUREX replies: "Please confirm the shutdown on your screen, sir."
5. Physical Verification: User taps button -> Callable runs `os.system("shutdown /s /t 0")`.
